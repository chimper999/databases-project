# AI and Entry Level Jobs Database

Group project for the Databases course, DSAI, Maastricht University.

This database stores data about how AI affects entry level job opportunities for new graduates.

## Files

The number in front of each SQL file is the assignment task it was written for.
That is not the same as the order you run them in, which is under
[How to run](#how-to-run).

- `sql/02-03_schema.sql` - relational schema, tables, constraints and the `AffectsWithLevel` view
- `sql/04_crud.sql` - insert, update and delete statements
- `sql/05_mock_data.sql` - mock data
- `sql/06_queries.sql` - advanced queries
- `sql/07_real_data.sql` - loads the real-world data (assignment 4, generated by `data/clean_transform.py`)
- `sql/08_queries.sql` - two more documented queries per group member (final assignment)
- `data/SOURCES.md` - real-world data sources, publication dates and licenses (assignment 4)
- `data/raw/` - raw dataset files (data_jobs filtered to entry-level rows, otherwise unchanged)
- `data/download_data.py` - downloads the raw datasets again
- `data/clean_transform.py` - cleans the raw data and generates `sql/07_real_data.sql` (needs Python 3 with pandas)
- `data/clean/` - cleaned tables as CSV and `cleaning_report.txt` with counts for every step
- `docs/data_cleaning.md` - schema violations, schema changes and all cleaning steps (assignment 4)
- `docs/normalization.md` - 3NF check with the real data, update to the week 2 report (assignment 4)
- `docs/limitations.md` - limitations and future work from the video, revisited with real data (assignment 4)
- `docs/queries.md` - every query, who wrote it, the question it answers and why it matters (final assignment)
- `docs/final_check.md` - final review of the schema and repository against every earlier week (final assignment)
- `docs/erd.mmd` - editable source of `docs/erd.png`
- `data/check_personal_data.sql` - scans the loaded database for personal data before publishing (final assignment)

## How to run

**Requirements:** MySQL 8.0.16 or newer (older versions ignore CHECK constraints).

Run the files in this order. Each step depends on the previous one:

```bash
mysql -u root -p < sql/02-03_schema.sql
mysql -u root -p < sql/05_mock_data.sql
mysql -u root -p < sql/07_real_data.sql
mysql -u root -p < sql/04_crud.sql
mysql -u root -p < sql/06_queries.sql
mysql -u root -p < sql/08_queries.sql
```

Or from inside the MySQL shell (started from the repository root):

```sql
SOURCE sql/02-03_schema.sql;
SOURCE sql/05_mock_data.sql;
SOURCE sql/07_real_data.sql;
SOURCE sql/04_crud.sql;
SOURCE sql/06_queries.sql;
SOURCE sql/08_queries.sql;
```

The schema file drops and recreates the `ai_entry_jobs` database, so you can always start over by running it again.

Note: `04_crud.sql` should only be run once. It inserts rows and then deletes some of
them again, so running it twice fails on the inserts. If that happens, run the files
above again from the top to reset the database.

## Open data

The data in this repository contains **no personal data**. Every graduate,
application, training course and AI adoption is invented by us: the names are
made up and the e-mail addresses use `example.com`, a domain RFC 2606 reserves
for documentation so that it can never belong to a real person. The real-world
data is about companies and job adverts, not about individuals.

This is checked, not just claimed. Run the check against the loaded database
and every row must come back with 0 hits:

```bash
mysql -u root -p ai_entry_jobs < data/check_personal_data.sql
```

The one exception is the phone number pattern, which is deliberately wide. Its
60 hits were all checked by hand and are salary figures, job requisition
numbers and year ranges, never phone numbers.
